# ChaosGrid plan: for the lead

This repo is ChaosGrid's plan: the milestones (docs/PLAN.md), the cards and the board (docs/tasks/), the workflow decisions (docs/WORKFLOW.md) and the changelog. The code repo is shared with other people, and keeps the rules, the protocol, the decisions about the code, the architecture, the conventions and the art (D73); `crew doc` lists both repos' docs. `crew lead` gives the lead agent this file, and crew's session hook gives it to every session started in the code repo; workers never read it. The lead and the workers run in the code repo.

- Change anything here only on a lead branch: `crew plan new <slug>`, edit and commit in its worktree, `crew plan check`, then `crew plan ready <slug>`. The human pushes, reviews and merges.
- The code repo's docs change on a lead branch there: `crew plan new <slug> --code`, limited to the globs in `.crew/lead-paths`. Keep them for everyone who works on the code: never mention crew, this repo, the cards, a task id or the plan there (D54, D73).
- A new card: `crew card new "<title>" --milestone M<n>` inside a lead worktree. The card format and the general planning rules are crew's (`~/Documents/AI/skills/crew/TASKS.md`); ChaosGrid's own are in docs/tasks/README.md › Planning rules.
- A running task needs a wider scope: `crew card widen T-NNN <glob>`. It prepares the lead branch and tells the worker to wait; after the human merges it, `crew merged` asks the worker to re-read its card.
- A decision changes: mark the old one `Superseded by Dn` and add the new row, with the next number that's free on both pages. One about the code goes in the code repo's DECISIONS.md, on a `--code` lead branch (DECISIONS.md › How decisions change); one about the workflow goes in docs/WORKFLOW.md, here. On a lead branch here, add a CHANGELOG entry and fix every card that relied on it. Merge the decision first, so no card points to one that isn't on main yet.
- Paths under `docs/` in cards mean this repo's file when it has one, else the code repo's. Nothing in the code repo cites a task, a milestone or this repo's docs: its code, comments and docs state the rule itself (D73).
- After a wave's merges, run `pnpm test:soak:full` on `main` in the background, in a lead worktree synced to `main`: workers run only the quick soak (D75). A failure becomes a fix card for the next wave, and the report gives the failing file and seed.
