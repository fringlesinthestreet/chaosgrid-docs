# T-089 — M4 end-to-end test and the web README

## Goal

M4 is done when a person can sign up, build and save a legal deck, and play a full game to 30 points with it, offline, against 3 bots in the browser, to test the game; a Playwright test walks that path. After this task `m4.spec.ts` is that test, against the real API and core, and `apps/web/README.md` explains the app to the next person who works on it.

## Interfaces

What exists (T-068 to T-088, T-100, T-104, T-106 and T-107):

```ts
// apps/web/e2e/support (T-074): signUp(page) → { username, password }; a fresh, seeded in-memory API per run
// Routes (APPS.md): /signup, /cards, /decks, /decks/new, /decks/:id, /play, /match, /replay
// The planning panel (T-086, T-087, T-100): grid cells are buttons named "col <c>, row <r>"; "Place Leader"; the plan list
// The deck editor (T-077, T-106): − / + per row, a click on a browser tile adds it, "Fits the Leader" (on once a Leader is set), "Legal" when checkDeck finds no problem;
//   leaving it with unsaved changes asks "Leave without saving?" (Keep editing, Discard changes)
// The match screen (T-085): Ready, and the top bar's points and point target; PlaybackControls (T-083): 4×, Skip
// The overlays (T-088): "Round N" banner, round summary, Log, the game-over modal (the winners, the final scores, Play again)
// The root README (T-107): "## Run it locally", the guide from a fresh clone to a game: setup, pnpm dev, each part alone, the settings, the DB, problems
```

What this task adds: `apps/web/e2e/m4.spec.ts` and `apps/web/README.md`. No app code.

## Deliverables

1. **`m4.spec.ts`, "a new player plays a game"** (one test, a 10-minute timeout), with every step checking the page it lands on:
   1. `signUp(page)`: lands on `/decks`, with no decks of the player's own and the starters listed.
   2. `/cards`: search for a starter Leader by name, open it: its rules text shows.
   3. Open a starter deck, Copy: the editor opens on the copy at `/decks/<id>`. Swap a card: − on a main-deck row (a problem shows), then click the tile of a main-deck card the deck doesn't hold ("Fits the Leader" is on, so it fits): the editor shows "Legal". Rename the deck "E2E deck" and Save: back on `/decks` it's listed as "Legal".
   4. `/play`: pick "E2E deck"; keep the three default opponents and the default point target; under More options set the seed `e2e-1`. Start: `/match` shows round 1 and Plan, and the top bar's point target is 30.
   5. Place Leader, then the cell "col 7, row 0": the plan list has one line, and once core answers, either the Leader's block is on the grid or the line is struck through with a reason. With the seed fixed, the answer is always the same: assert the one the run gives, and say which in a comment.
   6. Ready, then 4× and Skip until the Plan of round 2: the round summary for round 1 and the "Round 2" banner show.
   7. Ready and Skip each round until the game-over modal shows, at most 60 rounds: it names the winners, and a winner's final score is 30 or more. Play again opens `/play`.
   8. The console logs no errors at any point (`page.on('console')` and `page.on('pageerror')`), and every request goes to the web's own origin (`page.on('request')`): the game runs offline, with no art URL.
2. **`m4.spec.ts`, "an illegal deck can't be played"**: sign up, `/decks/new`, pick a Leader, add one card, name it and Save. The list shows it "Not legal", and on `/play` it's dimmed and can't be picked, with a link to edit it.
3. **`apps/web/README.md`**, about 150 lines at most:
   - What the app is, and how to run it in a few lines that link to the root README's guide (`../../README.md#run-it-locally`, T-107) instead of repeating it, plus the worker ports (`CHAOSGRID_WEB_PORT`, `CHAOSGRID_API_PORT`).
   - The folders and what each owns (APPS.md's layout, without the task numbers), and the import rules ESLint checks (T-068):
     - Only `src/host/` imports core, through its public entry. Only `match/session.ts` uses values from `src/host/`; other folders import its types.
     - `@chaosgrid/bots` only in `src/lobby/` and `src/host/`.
     - Every feature calls the API through `src/api/`. Nothing else calls `fetch` but the art manifest (`src/art/manifest.ts`).
   - The match's data flow, as one diagram or list: lobby → `MatchSetup` → session → host (core, bots) → transport → events → playback → model → battlefield and overlays; snapshot → planning panel → `plan.submit` → `plan.checked`.
   - The rules a change must keep: the UI never reads core state; legality is core's (D29), and the panel disables a control only on a fact the snapshot states; art lives in `src/art/`, keyed by card id or a `ui.<name>` key (D13), and pages draw card art only through `CardArt`; never hard-code the tick rate.
   - Tests: Vitest and its fixtures (`test/fixtures/logs/` and how to remake them with sim-cli, `test/fixtures/session.ts`, `test/fixtures/planning/`); Playwright, its ports and its in-memory DB.
   - Art (D39): the repo holds only placeholders; real art is files in a bucket, listed by `manifest.json` under `VITE_CHAOSGRID_ART_URL`. To add a card's art, upload the file under its content hash and list its key in the manifest, with no code change. With the URL unset (tests, the e2e, a local game), everything draws placeholders.

## Notes

- Find elements by role and accessible name (`getByRole('button', { name: 'Ready' })`), not by CSS classes, so the spec survives restyling. Where a name is missing, that's a request to the folder's owner, not a test ID added here.
- Skip playback with the Skip button: a whole game at 1× would take minutes. Wait on what the page shows (the round label, the Ready button), never with fixed sleeps.
- Every game has three bots (D22), so the spec covers four seats and the rotation of the arena.
- The e2e runs with `VITE_CHAOSGRID_ART_URL` unset: every sprite is a placeholder, so it needs no art URL or bucket.
- Default: if the game with seed `e2e-1` doesn't end within 60 rounds or the timeout, pick another seed and name it in the PR.
