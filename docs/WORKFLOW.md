# ChaosGrid — Workflow decisions

How the maintainers plan and run the work: the agents, the task cards, the lead and this repo. The code repo's `docs/DECISIONS.md` keeps the decisions about the code. These moved here from it with their numbers (D54), copied as they were, so "this repo" in them means the code repo, and a `scripts/` file or docs/agents/ means its crew equivalent (D53).

They change like the code's: never rewrite or delete one. Set its status to `Superseded by Dn` and add the replacement as a new row, with the next number that's free on both pages, on a lead branch here, with a CHANGELOG entry.

| # | Status | Decision | Why | Revisit when |
|---|---|---|---|---|
| D14 | Accepted | **Agents work from pre-planned task cards, with one branch and one worktree each, and coordinate through a local Redis.** Humans push and merge (`CLAUDE.md`, `docs/agents/`) | Parallel agents don't collide, and every change arrives as a reviewable PR | The workflow slows us down more than it protects |
| D15 | Superseded by D16 | **Progress is read from git.** A task is done once `main` has a commit that either has a subject ending in `(T-NNN)` (the PR title convention; GitHub adds ` (#12)`) or carries a `Task: T-NNN` trailer. The status in README.md is generated from that by `scripts/status.sh` and never edited by hand | One source of truth that can't drift from what's actually merged; it works without Redis | Task tracking moves to GitHub Issues or Projects |
| D16 | Accepted | **PR titles are `T-NNN <card title>`, and progress is read from git.** PRs are squash-merged with the PR title as the commit message. A task is done once `main` has a commit whose subject starts with `T-NNN ` (GitHub adds ` (#12)`). A `Task: T-NNN` trailer also counts, and so do older subjects that end in `(T-NNN)`. A commit listed in `scripts/not-task-merges` never counts: it only looks like a task merge. The status in README.md is generated from that by `scripts/status.sh` and never edited by hand | Short, readable PR titles and one commit per task on `main`; one source of truth that can't drift from what's merged, and works without Redis | Task tracking moves to GitHub Issues or Projects |
| D17 | Accepted | **Agent sessions are kept small and run on the cheapest model that fits.** Workers run on their card's `model` and `effort` (default sonnet, medium), the lead on sonnet. Agent sessions compact at 150k tokens. Workers read through `scripts/context.sh` and line ranges, run the gates with the quiet `scripts/check.sh`, and report in five lines. One lead session per wave | M1 used a weekly budget in a day: 99% of it was the context re-read at every step, in sessions of 200k–650k tokens on Opus | Quality drops on sonnet, or `scripts/tokens.sh` shows that the context isn't the cost any more |
| D36 | Accepted | **Lead changes reach `main` only as reviewed PRs from `lead/<slug>` branches.** The lead, human or agent, never commits on `main`: a card, a scope, a decision, a doc or a lead script changes on a `lead/<slug>` branch in its own worktree (`scripts/plan.sh`), and the human pushes it, reviews it and squash-merges it like a task's PR. A lead branch changes only the files in `scripts/lead-paths` as `main` has it; code, card data and CI change through a task card. Its commits and its PR title are Conventional Commits that never look like a task merge (D16). A git pre-commit hook refuses commits on `main` from Claude Code shells, and the `Agent scope` check enforces the list on `lead/` PRs (LEAD.md › Lead branches) | A scope fix or a card change committed straight to `main` skipped the review every worker's change gets, and a mistake in a card misleads every worker that reads it. A branch per change also keeps the main checkout clean for `merged.sh` to pull | Review of small card fixes holds a wave up for longer than the mistakes it catches cost |
| D53 | Superseded by D73 | **This repo is shared: it keeps the code and the docs anyone working on it needs, while the plan lives in the maintainers' private repo, chaosgrid-docs, and the agent workflow runs on the maintainers' `crew` tool.** Here, in docs/: RULES, PROTOCOL, DECISIONS, ART, ARCHITECTURE (the layout, the runtime shape and the card JSON sketch, from PLAN.md) and the conventions, CORE (from the M1 README) and APPS (from the M4 README). In the plan repo: the milestones (`docs/PLAN.md`, so `PLAN.md › M<n>` in a comment points there), the task cards and the board (`docs/tasks/`), the changelog, the status block, the notes for crew's workers and crew's settings. CLAUDE.md is for anyone working on the code; crew's own rules come with its commands and the plan. The lead changes the plan on lead branches there, and the docs here on lead branches here (`crew plan new <slug> --code`), limited to the paths the plan repo's `.crew/lead-paths` lists. `pnpm dev` runs only the game. D14, D16, D17 and D36 still hold: where they name a `scripts/` file or docs/agents/, read its crew equivalent | The repo is going to be shared with other people. The plan, its history and the tooling are the maintainers' business, while the docs that explain the code belong next to it. About half of main's commits were status and plan bookkeeping | Planning needs a code change and a plan change merged together, or the shared docs and the plan drift apart |
| D54 | Accepted | **The code repo names neither crew nor this repo.** Its files, commits and PR texts are for anyone who works on the code. The workflow decisions (D14–D17, D36, D53) moved here, and the code repo keeps a one-line `Withdrawn` row for each number. A Claude Code session learns the workflow from crew's session hook, which `crew setup` writes to the code repo's untracked `.claude/settings.local.json`, and a worker from its prompt. A session the human starts is the lead: the docs and the cards change on lead branches, and anything else gets a task card first. A session started by hand didn't know it was the lead: it made a branch in the main checkout instead of a lead branch | Someone other than the maintainers pushes agent branches, so GitHub has to enforce the scope again |
